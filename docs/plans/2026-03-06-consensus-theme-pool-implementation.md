# Consensus Theme Pool Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the old category-scanning theme pool generator with a 5-method consensus pipeline + interactive human curation UI.

**Architecture:** The skill orchestrates 5 parallel Claude Code subagents that each produce a raw JSON word list. A Node.js script merges, JPDB-enriches, and generates a master list + review HTML. The user curates via checkboxes in the browser, then submits. A server endpoint receives the selection and writes the final theme pool JSON.

**Tech Stack:** Node.js scripts (ESM), Express endpoint, self-contained HTML/JS review UI, JPDB API, Claude Code subagents (Opus).

### Task 1: Create the consensus enrichment script

**Files:**
- Create: `scripts/theme-pool-consensus.mjs`

This script takes 5 raw JSON files (one per method), merges them, enriches via JPDB, and generates the master JSON + CSV + review HTML.

**Step 1: Write the script**

CLI interface:
```bash
node scripts/theme-pool-consensus.mjs \
  --theme school \
  --area-word 学校 \
  --area-reading がっこう \
  --area-meaning school \
  --input tmp/theme-school-1-brainstorm.json \
  --input tmp/theme-school-2-jisho.json \
  --input tmp/theme-school-3-textbook.json \
  --input tmp/theme-school-4-scene.json \
  --input tmp/theme-school-5-web.json
```

The script must:

1. **Read all 5 input files.** Each is `[{word, reading, meaning}, ...]`. Track which method each word came from via the filename (extract method name from the `-N-name` pattern).

2. **Merge and deduplicate.** Build a `Map<word, {reading, meaning, methods: Set<string>}>`. When a word appears in multiple files, merge method names. Keep the first non-empty reading/meaning encountered.

3. **JPDB enrichment.** Reuse the existing `parseBatch` and `lookupVocab` from `scripts/lib/jpdb-helpers.mjs`:
   - Parse all unique words (batches of 30, 1s delay)
   - Lookup vid/sid pairs for rank, POS, meanings (batches of 500, 1s delay)
   - API key from `data/.creature-forge-jpdb-key` or `JPDB_API_KEY` env var

4. **Filter.** Remove words with `rank > 30000` or `rank === null`. Deduplicate by vid.

5. **Build master list.** Each entry:
   ```json
   {
     "word": "教室",
     "reading": "きょうしつ",
     "meaning": "classroom; lecture room; ...",
     "rank": 1500,
     "tier": "common",
     "pos": "n",
     "brainstorm": true,
     "jisho": true,
     "textbook": true,
     "scene": true,
     "web": true,
     "consensus": 5
   }
   ```
   Sort by consensus desc, then rank asc.

6. **Look up area word rank.** Parse + lookup the area word itself to get `areaRank`.

7. **Write outputs:**
   - `tmp/theme-<id>-master.json` — the full master list + metadata
   - `tmp/theme-<id>-master.csv` — CSV version
   - `tmp/theme-<id>-review.html` — self-contained review UI (see Task 2)

The master JSON wraps the list with metadata:
```json
{
  "themeId": "school",
  "areaWord": "学校",
  "areaReading": "がっこう",
  "areaMeaning": "school",
  "areaRank": 700,
  "generatedAt": "2026-03-06",
  "methodCounts": { "brainstorm": 429, "jisho": 622, ... },
  "words": [ ... ]
}
```

**Reuse from existing code:**
- `parseBatch`, `lookupVocab`, `tierFromRank` from `scripts/lib/jpdb-helpers.mjs`
- API key loading pattern from `scripts/generate-theme-pool.mjs` lines 63-77

**Step 2: Verify it works with the existing bake-off data**

### Task 2: Build the review HTML template

**Files:**
- Modify: `scripts/theme-pool-consensus.mjs` (add HTML generation function)

The review HTML is generated by the consensus script (Task 1) with word data embedded as a JS variable. This task defines the HTML template that gets embedded.

**Step 1: Add the HTML generation function to the consensus script**

The HTML must include:

**Layout:**
- Sticky header with title, search bar, filter buttons, sort buttons, stats
- Scrollable table with checkbox + word + reading + meaning + rank + 5 method columns + consensus

**Interactive features:**
- Checkbox on every row (all unchecked by default)
- Filter by consensus (All, 5/5, 4+, 3+, 2+)
- Filter by tier (All, Common, Uncommon, Rare, Epic, Legendary)
- Sort by consensus, rank, or word
- Text search across word, reading, meaning
- "Check all visible" / "Uncheck all visible" bulk buttons
- Counter showing "X of Y selected"

**Submit flow:**
- "Submit" button at bottom (sticky footer)
- On click: collect all checked words, POST to `/api/theme-pool/submit` with theme metadata + selected words
- Show success/error message
- The POST body includes `themeId`, `areaWord`, `areaReading`, `areaMeaning`, and the `words` array

**Styling:** Dark theme matching the bake-off review page already built. Mobile-friendly (user reviews on phone).

**Key detail:** The server URL for the POST must be the current page origin (so it works on both localhost and the remote server). Use `window.location.origin` as the base.

### Task 3: Add the server endpoint for theme pool submission

**Files:**
- Modify: `server.js` (add POST `/api/theme-pool/submit` route)

**Step 1: Add the endpoint**

Find the section of server.js where API routes are defined (look for other `/api/` routes). Add:

```javascript
// POST /api/theme-pool/submit — finalize a theme pool from the review UI
app.post('/api/theme-pool/submit', express.json({ limit: '2mb' }), async (req, res) => {
  // ... implementation below
});
```

The endpoint must:

1. **Validate input.** Require `themeId`, `areaWord`, `areaReading`, `areaMeaning`, `words` (array).

2. **Assign roles.** Use `assignRoles()` from `scripts/lib/theme-pool-helpers.mjs`. But since server.js is CommonJS and the helpers are ESM, use dynamic `import()`:
   ```javascript
   const { assignRoles, crossReferenceExisting, computeThemeStats } =
     await import('./scripts/lib/theme-pool-helpers.mjs');
   const { saveTheme, validateTheme } = await import('./scripts/lib/theme-utils.mjs');
   ```

3. **Cross-reference existing game data.** Call `crossReferenceExisting(words)`.

4. **Build theme object.** Format each word with: word, reading, meaning, rank, roles, source (set to method names that found it, e.g. "brainstorm,scene,web"), consensus, assigned: null, existingUses.

5. **Compute stats.** Call `computeThemeStats(words)` for avgRank, computedStage, roleCounts.

6. **Look up area rank.** The master data already has this — pass it from the client.

7. **Validate and save.** Call `validateTheme(theme)` then `saveTheme(theme)`.

8. **Return** `{ success: true, themeId, wordCount, computedStage }`.

**Step 2: Test the endpoint**


### Task 4: Rewrite the generate-theme-pool SKILL.md

**Files:**
- Modify: `.claude/plugins/koto-forge/1.1.0/skills/generate-theme-pool/SKILL.md`

**Step 1: Rewrite the skill**

The new skill flow:

**Phase 0: Setup** (same as before)
- Input: theme concept + optional area word
- If no area word, brainstorm 3-5 candidates via JPDB, user picks one
- Set themeId = lowercase English concept

**Phase 1: Launch 5 agents in parallel** (NEW)

Launch all 5 as background agents. Each writes to `tmp/theme-<themeId>-N-<method>.json`.

Each agent prompt should be a template with `{THEME}` and `{THEME_SCENES}` placeholders that the skill populates based on the theme concept. The prompts are the same ones used in the bake-off (see `docs/plans/2026-03-06-consensus-theme-pool-design.md`).

Agent output format: `[{word, reading, meaning}, ...]`

**Phase 2: Wait for agents, run enrichment** (NEW)

Once all 5 complete:
```bash
node scripts/theme-pool-consensus.mjs \
  --theme <themeId> \
  --area-word <word> --area-reading <reading> --area-meaning <meaning> \
  --input tmp/theme-<id>-1-brainstorm.json \
  --input tmp/theme-<id>-2-jisho.json \
  --input tmp/theme-<id>-3-textbook.json \
  --input tmp/theme-<id>-4-scene.json \
  --input tmp/theme-<id>-5-web.json
```

**Phase 3: Serve and present** (NEW)

Start HTTP server if not running:
```bash
cd tmp && python3 -m http.server 8766 --bind 0.0.0.0 &
```

Present the review URL to the user:
```
http://srv1438246.hstgr.cloud:8766/theme-<themeId>-review.html
```

Show summary stats (total words, per-method counts, consensus breakdown).

**Phase 4: User curates and submits** (NEW)

Tell the user to:
1. Open the review URL on their phone/browser
2. Check the words they want in the pool
3. Hit Submit

The skill waits for confirmation that the pool was saved, then validates:
```bash
node scripts/generate-theme-pool.mjs --validate <themeId>
```

**Phase 5: Commit** (same as before)
```bash
git add language/themes/<themeId>.json language/themes/<themeId>.csv
git commit -m "feat: add <themeId> theme pool (N words, stage X)"
```

**Step 2: Also generate a CSV export after submit**

The server endpoint should also write a CSV alongside the JSON for easy spreadsheet review. Add this to the submit endpoint logic in Task 3.

**Step 3: Commit**

```bash
git add .claude/plugins/koto-forge/1.1.0/skills/generate-theme-pool/SKILL.md
git commit -m "feat: rewrite generate-theme-pool skill for consensus-based pipeline"
```
