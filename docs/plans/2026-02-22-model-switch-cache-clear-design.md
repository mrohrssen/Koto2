# Design: Clear Dialogue Cache on Model Switch

**Date:** 2026-02-22

## Problem

When a user switches their AI provider or model in settings, cached NPC and creature dialogues remain — generated by the old model. The user has no way to force regeneration with the new model short of manually hitting debug endpoints.

## Solution

When saving settings, detect if the AI provider or model changed. If so, prompt the user to clear all cached dialogue. On confirmation, clear both NPC and creature dialogue caches for that user. Regeneration happens naturally on next exploration start.

## Trigger

On settings save in the frontend, compare `aiProvider`, `openaiModel`, and `openrouterModel` before and after. If any changed, show a `confirm()` dialog.

## What Gets Cleared

- NPC dialogue cache (disk + in-memory) — via existing `POST /api/game/clear-npc-dialogue-cache`
- Creature dialogue cache (disk + in-memory) — via new `POST /api/game/clear-creature-dialogue-cache`

## What Does NOT Get Cleared

- NPC memory (encounter counts, bond scores, befriended/liberated flags)
- Creature memory (encounter counts, befriended flags)

## Regeneration

Both NPC and creature dialogues pre-generate in the background on exploration start (`run.js:61-81`). After cache clear, next exploration run rebuilds everything with the new model.

## Backend Change

Add `POST /api/game/clear-creature-dialogue-cache` endpoint in `src/routes/game/misc.js`, mirroring the existing NPC clear endpoint. The `clearCreatureDialogueCache` function is already exposed by the narration engine — it just needs a route.

## Frontend Change

In `public/js/settings.js` `saveApiKeys()` (or wherever the save action fires):
1. Snapshot current provider/model values before writing
2. Write new values to localStorage
3. Compare — if changed, `confirm("You switched AI models. Clear cached dialogue so it regenerates with the new model?")`
4. If yes, `fetch('/api/game/clear-npc-dialogue-cache', { method: 'POST' })` and `fetch('/api/game/clear-creature-dialogue-cache', { method: 'POST' })`
