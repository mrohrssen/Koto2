# Capacitor Bundled iOS Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the production iOS Capacitor app load the bundled `dist` web shell instead of downloading app code from `https://jrpg-production.up.railway.app` through `server.url`.

**Architecture:** Remove production `server.url` from Capacitor config so WKWebView starts from the app bundle (`capacitor://localhost`) and uses the existing `PLATFORM.apiBase` fallback for remote API calls. Preserve remote live-reload only through an explicit environment variable, so dev builds can still point at a local Vite server without making production builds remote-code shells.

**Tech Stack:** Capacitor 8, iOS WKWebView, Vite `dist`, Node test runner, existing Koto auth/API layer.

---

## Scope

This plan implements only the first architecture change: production iOS loads bundled web assets. It does not add offline gameplay, native asset downloaders, API response caching, code splitting, or new App Store release automation.

- [ ] **Step 1: Implement the helper**

Create `src/capacitor/native-server-config.js`:

```js
function normalizeServerUrl(rawUrl) {
  let parsed;
  try {
    parsed = new URL(rawUrl);
  } catch {
    throw new Error('KOTO_CAPACITOR_SERVER_URL must be a valid URL');
  }

  if (parsed.protocol !== 'http:' && parsed.protocol !== 'https:') {
    throw new Error('KOTO_CAPACITOR_SERVER_URL must use http or https');
  }

  return parsed.href.replace(/\/$/, '');
}

export function buildNativeServerConfig(env = process.env) {
  const rawUrl = String(env.KOTO_CAPACITOR_SERVER_URL || '').trim();
  if (!rawUrl) return undefined;

  const url = normalizeServerUrl(rawUrl);
  const cleartext = url.startsWith('http://');

  if (cleartext && env.KOTO_CAPACITOR_ALLOW_CLEARTEXT !== '1') {
    throw new Error(
      'HTTP Capacitor live reload requires KOTO_CAPACITOR_ALLOW_CLEARTEXT=1'
    );
  }

  return { url, cleartext };
}
```

## Release Notes For The Implementer

- After this change, web deploys no longer update the iOS app shell. UI/code changes require a new iOS build/release, while server/API/content behavior can still change on Railway.
- Keep `public/js/platform.js` production fallback intact. Bundled native loads from `capacitor://localhost`, so same-origin `/api/...` would be wrong without the remote API base.
- Do not enable `KOTO_CAPACITOR_SERVER_URL` in production CI/App Store builds. It exists only for explicit live-reload/dev workflows.
- This change reduces startup network dependence but does not make gameplay offline. Auth, saves, AI dialogue, TTS generation, PvP, and bug reports still require the server.
